# hololive Dreams 启动登录顶层经验

关键词：hololive_dreams hololivedreams holodori 启动 登录 每日奖励 继续 主界面。
位置：项目顶层共享知识库，与 domains/hololive_dreams 的游戏内经验分开。
来源：用户于 2026-10-02 说明；user_reported，未独立验证所有每日奖励类型。

Steam 启动或切回窗口只完成程序启动，必须继续处理登录和首次每日奖励。大部分页面可点击游戏画面中央推进，或点击当前弹窗 X；经常出现“继续”提示，优先定位并点击该文字。原生窗口右上角关闭按钮不能当弹窗 X。

结束目标：画面出现自由主界面的活动、游戏、演出、任务、成就、扭蛋 HUD（当前规则至少匹配四个），且没有仍待处理的每日奖励/继续提示。此界面是强欲之牌入口树的起始状态。加载更新时等待；购买、错误、验证码等不盲点。地图或小游戏页面不由启动树强行退出，应交回对应组件。

本地实现：src/modular_agent/agent/startup_tree.py，版本1.0.2。顶层 launch_game 会串行启动 Steam 再运行本地树；未知或失败交回模型。直接运行 run_game_startup.cmd 或 local-start --domain hololive_dreams --live。不请求联网大模型，所有目标坐标来自当前完整观察；鼠标按 Alt，停止后释放键鼠。中央点击最多8次，普通状态最多三次，超时或人工引导返回顶层。

该组件只到自由主界面，不进入或游玩小游戏。回滚可使用底层 GameLauncher，仅切回窗口，再由顶层处理登录。

## 加载缓冲修正（2026-10-02）

实际日志 agent-20261002-155216-580090.log 中 Loading... 未识别为加载，之后 APTO START / TAPTOSTART 被误当未知页，导致两次中央探测预算耗尽。现将 Loading/Connecting/Downloading 识别为等待，支持 TAP TO START 及 APTO START OCR 变体，定位启动文字点击。

空白/只有窗口标题的页面先等待，加载与空白默认最多120秒，不按观察次数提前求助。其他未知过渡给6秒缓冲，再有限中央探测；已点击的同类按钮至少等待6秒，不重复点。总超时仍为240秒，明确错误、验证码和人工停止不受加载缓冲延后。

## 闪烁提示与积极中央点击（用户补充）

游戏启动文字会闪烁，大部分推进可点击游戏中央。当前版本1.0.2：启动提示和“继续”默认点击当前游戏画面中央；未读到文字或只有窗口标题时给6秒短缓冲后也尝试中央，不要求提示始终可见。同一组件最多8次中央点击，每次间隔至少6秒，即使OCR闪烁导致状态名称变化也不连续点。已定位奖励 X 仍优先关闭。明确加载文字仍等待，错误/验证码立即交回；到自由主界面立即结束，不把积极点击延伸到游戏内。

此节替代此前“未知过渡等待30秒／中央探测两次”的限制。
