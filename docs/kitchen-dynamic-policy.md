# 厨房动态置信度与强化残局

入口：厨房控制窗口 → 高级策略参数。普通参数、动态置信度与强化残局开关、高级参数均保存到runtime/kitchen/control/preferences.json；修改后下一次开始生效。

## 默认值

| 参数 | 默认 |
| --- | --- |
| 正常置信度 | 0.25 |
| 最低候选门槛（主窗口） | 0.12；0关闭降门槛 |
| 置信度上限 | 0.40 |
| 每轮最多下降 | 0.04 |
| 空槽吃紧最多提高 | 0.05，受上限限制 |
| 降门槛至少空槽 | 4 |
| 降门槛正常分数目标上限 | 8 |
| 上轮少点击界限 | 3 |
| 空槽／稀疏／少点击权重 | 0.7／0.2／0.1 |
| 强化残局可见目标上限 | 6 |
| 强化残局至少空槽 | 4 |
| 强化残局至少保留 | 2格 |
| 强化残局最多额外零散点击 | 3 |

## 实际执行

首轮用正常值。之后使用同一帧、去重后的目标数、当前较保守空槽数和上一轮真实发送点击数。空槽数取视觉占用与台账占用较大者计算，不因预计三消而提前增加。没有可靠新鲜槽位证据，不降门槛或多拿零散目标；空槽不足时立即恢复/提高门槛。画面仍密集、低分候选过多或上轮还大量点击，保持正常值。

条件允许时，把空槽、稀疏和少点击评分加权，向最低门槛逐轮下降；空槽权重必须不小于另两项之和。当前默认：7空槽、仅1个正常分数目标、上一轮0点击时，约0.25→0.21→0.17→0.13→0.123。输入变密集、容量收紧会恢复或提高，非单向无限下降。

一轮仍只做一次神经网络推理，先取得最低门槛候选，再按动态值筛选，不额外重跑模型。用户配置的最低值以下目标依然无法找回。

补齐已有同类与完整三消先规划；强化残局随后按已有同类、面积和置信度挑选零散目标，同类连续发送。额外点击数≤用户零散上限、每轮剩余点击数、当前空槽−残局预留−本轮已规划点击数。最后一项是原始发送预算，不假定之前任何三消一定成功。执行器另有同样的原始预算，防止发送过程中多拿。普通取物仍按普通预留值约束。

关闭强化残局保留之前的全可见目标少于空位时清场规则；关闭动态置信度则使用固定正常门槛。只点击指定食材、去重、每轮点击上限、页面/焦点/F12守卫全部保留。总时长与总局数不限。

## 可复查性与限制

每轮decision事件记录实际门槛、空槽、正常目标数、低分候选数、上轮点击数、槽位可靠性与调整原因。诊断回放优先展示当时记录，不拿后来参数覆盖旧决策。

“可见框少”不是证明真实棋盘接近清空；遮挡与漏检仍可能让估计失真。槽位可靠性也是当前视觉启发式，并非真实游戏状态。已做容量穷举、低分/密集/首轮/关闭/未知槽位/降幅上限、参数重启保存与CLI透传测试；尚未实机确认新策略的胜率。
