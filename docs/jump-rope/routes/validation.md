55秒背景样例较旧受限形状方案约84px的偏离改善明显；14秒旧自由曲线约6px，本路线约8.7px，并没有全面超过旧方案。20秒旧受限形状约2.4px，本路线偏离82px，单一普通旋转轨迹仍会在技能段失配。32秒模型严重偏离，必须显示为预测，不能当检测成功。

最终对照图位于 `runtime/jump-rope/phase/validation-contact.jpg`，分别展示4、14、20、32、55、70秒。20、32、70秒估计速度跌到0.02圈/秒附近，阶段近乎停滞；70秒候选阶段虽接受了视觉证据，当前曲线却没有支持点。因此问题还包括阶段歧义与速度更新，不能只归因于绳子颜色。

本次验证了固定路径约束形状、阶段连续推进、失去图像时保留假设，但所有模式尚未准确跟踪。下一步增加独立低空摇摆轨迹、多阶段假设与速度重新定位，再验证危险经过和短按时机。置信度目前是启发值，不是成功概率。

## 失败原因复查（2026-10-04）

逐帧统计保存在runtime/jump-rope/phase/failure-analysis.json。本次仅分析，未修改识别或自动输入逻辑。

1. 代码级错误：PhaseTracker.update在判定observed是否通过gate之前已经修正阶段和速度。因此不被接受的观测仍能影响状态。录像中有99个已锁定、高质量候选但observed=false的帧实际改变了速度。
2. 门控链路不完整：候选阶段接受后先提升confidence并缩小uncertainty，再检查当前保留曲线附近是否有支持。1717帧阶段observed=true而rope_valid=false；这些帧不全是误认，但说明没有足够曲线验证的候选仍可维持锁定。70秒候选覆盖约49%，当前曲线覆盖0，仍更新阶段置信度。
3. 速度以每帧阶段残差更新，候选阶段离散为96档；没有独立连续片段位移/多帧相位斜率核对，也没有正反分支的竞争假设。17秒约0.872圈/秒，18秒跌至下限0.02圈/秒，整段128次触及下限。残差持续负值可把速度压低，此时附近候选继续强化错误状态。
4. 搜索自锁：uncertainty常被上述候选压回0.012圈，平时只搜索预测附近约±0.084圈。每30帧全圈检查仍带有预测距离惩罚；不是一次独立无偏重获取。固定路径只限制形状，并不证明所在阶段正确。
5. 图像证据仍不具备唯一性：灰度细条、边缘与像素变化可来自障碍物/背景；当前运动分数仅加分，锁定后不要求足够当前运动。遮挡、变亮可把真绳细条特征削弱。近期灰度变化包络不等同于完整静止背景模型。
6. 模式资产不全：只有一圈普通旋转模板，没有低空左右摇摆模板或模式切换。不能把所有技能段都当成同一普通旋转周期。具体错误帧是否还存在路径几何偏移，需要按模式人工标注核对，当前资料不足以量化。

下一步顺序：先把观测门控移到任何状态更新前；让当前曲线证据参与置信度更新；保留多个阶段/方向假设并按连续多帧证据更新速度；失配时扩大搜索、降低先验惩罚；随后补摇摆轨迹。应保持原版本供对照，用同一录像比较失败样例与误报，不能只追求观测帧数增加。
