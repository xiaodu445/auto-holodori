# 固定轨迹反向 v2

2026-10-04。独立实验C2，解决左右摇摆允许运动方向反转的需求。复用普通旋转路径库，没有重新拟合绳形，没有修改A路线自动跳跃、C/v1前向算法或顶层观察行为。

## 运行与回退

双击run_jump_rope_phase_reverse_judgment.cmd，或统一菜单按0。3秒准备后切回游戏，预览显示有符号rate、direction、turns和pending；不发送空格。F12/Ctrl+C/切走停止；识别丢失继续预测，不当成功。默认会话仍有180秒时限。

CLI为--phase-rope --phase-reverse；缺少--phase-rope会拒绝。真实输入/test-space组合在接触桌面前拒绝。要回到原轨迹预测，运行run_jump_rope_phase_judgment.cmd；自动跳跃仍用run_jump_rope_local_motion.cmd。

## 改动范围

SignedPhaseTracker独立保存在src/modular_agent/realtime/phase_tracking.py；原PhaseTracker保持。领域视觉和曲线库复用，按独立配置allow_reverse=true选择估计器。配置在domains/hololive_dreams/models/jump_rope/jump_rope_phase_reverse_config.json，C/v1配置不改。

- rate允许正、负与零；方向表示路径阶段前进或后退，不直接等于屏幕左右。
- 最近约0.18秒、最多10个有效阶段样本做加权直线斜率。至少4点、跨度65ms；转向证据要求净位移0.018圈、拟合残差不超过0.018圈、70%以上有效增量方向一致。
- 连续3次满足相反方向且斜率超过0.06圈/秒才确认反向；此前目标速度可以降为零，不能因一个候选反跳。最大速度4圈/秒，最大加速度8圈/秒²。
- 阶段用连续历史展开，允许跨0/1向两个方向运动。转折期间位置连续，按确认方向限制相位修正，每次最多min(0.025,dt)圈。转向确认有延迟，不等于物理转折帧。
- 候选先经过质量、相位/相邻样本位移检查，再更新阶段与速度。连续的视觉片段可以偏离旧前向预测以收集转向证据；不连续候选被拒绝且不能改变速度和运动历史。
- 图像丢失保留方向与速度，但置信度下降、不确定范围变大；超过120ms没有有效候选清空速度拟合窗口再获取，不能跨长遮挡判断实际是否发生反转。

候选视觉评分、96档阶段、灰度边缘/细条与运动信息保持同一实现，仍可能选中背景，没有真实摆动独立轨迹。允许沿现有路径往返，不证明摆动几何与普通旋转库完全相同。反向帧数与支持帧数不是准确率。视觉候选与最终曲线支持仍是不同层次，尚未解决所有低置信度反馈问题。

## 用户反馈与待修正项（2026-10-04）

用户实测反馈：正转各种技能条件下跟踪表现很好，反向约60%的情况稳定，但会突然挂在下半圈，低空摇摆也可能脱离预测。这是用户估计，不是程序统计准确率。

用户进一步确认：声音可提前提示低空摇摆，且每次左右低空摆结束后一定换方向。声音提示尚未采集或接入；可先用视觉确认摆动区间、转折和退出，再将换方向规则用作方向先验，不能在尚未确认摆动时强制翻转。

代码检查发现另一种卡住路径：负速度正常推进时，相位位置修正可能朝反方向抵消推进；最后min(previous_phase,corrected_phase)把位置夹回原处。若附近错误候选继续被接受，历史速度仍为负，模型位置却连续不变，confidence仍可能刷新。保存录像中存在这种组合，详见phase-reverse/stall-analysis.json；没有最新实时last-result.json，因此尚不能断言用户这次卡住恰好都是该原因。

后续应区分真实转折停顿与“有运动速度但阶段长期不动”：普通旋转中不能让低可信位置修正无限抵消推进；触发扩大搜索/多阶段候选并降低错误锁定置信度。低空摇摆须允许真实端点停顿，并单独维护摆动及退出后换向的状态。保持目前良好的正转路线作为对照。本条只记录分析和新规则，尚未修改估计器或接入声音。


已新增独立[三状态v3](fixed-phase-state.md)作对照，v2代码/配置与本入口不变。v3限制长停滞并使用有限低空路径，当前仍只判断。
