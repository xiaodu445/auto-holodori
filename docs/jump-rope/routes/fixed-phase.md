# C：固定轨迹＋阶段跟踪 v1

更新：2026-10-04。独立实验，不替换A自动路线；只判断，任何live/experimental-live/test-space组合均在打开桌面或输入前拒绝。CLI为--phase-rope；不能与local/shape/whole同时启用。

## 核心约定

按用户说明，普通旋转有固定运动路径，速度可变。C保存C(s)：阶段s对应一整条41点曲线；运行时仅更新阶段和推进速度，不给各个点自由寻找位置。s是参考录像一圈中的进度，不是已校准的3D角度或危险阶段。

始终保留一条曲线假设，包括未获取/长遮挡时；灰色只是先验或不确定模型，不是检测成功。画面提供可见片段证据来纠正阶段与速度；没有图像支持时沿已有轨迹推进、置信度衰减、不确定范围增大，不因not_observed自动退出。旋转的展开阶段不反向突跳；修正每帧最多min(0.025,dt)圈，速度变化限幅。加减速不按参考周期固定发键。首次三帧一致获取允许重新定位，灰色初始化阶段不算已经连续跟踪。

当前是单阶段假设，不是多假设粒子/深度模型。置信度与uncertainty为实验启发量，尚未统计标定，不可当成功概率。视觉候选阶段被接受也不等于当前模型每个点认准；rope_valid另要求当前曲线附近至少8个可见支持点，绿色点有像素距离检查。预测曲线存在、候选证据、当前曲线支持分别输出。

## 代码和参数

- 通用数学组件：src/modular_agent/realtime/phase_tracking.py，CyclicTrajectory/PhaseTracker。
- 领域视觉/只判断控制：domains/hololive_dreams/models/jump_rope/jump_rope_phase.py。
- 独立配置：jump_rope_phase_config.json（atlas路径、max_rate、max_acceleration、inference_width、input_enabled=false）。窗口ROI为[.17,.02,.88,.72]，内部宽度640；按客户区归一化。窗口移动/缩放由共用框架处理并重置；改变纵横比/游戏出现黑边仍需重新校准游戏区域。
- 共用接口：jump_rope.py CLI/回放、keyboard.py实时循环、jump_rope_preview.py预览。无逐帧OCR、UIA、全屏匹配或大模型请求。

视觉不按当前绳色筛选，用固定轨迹上的灰度边缘、法线两侧亮/暗细条对比和近期像素变化评分。角色身体核心有保守位置排除先验（不是自动识别框）。可靠时只评估预测附近阶段，每30帧做全圈搜索；不确定性增大时扩大范围。遮挡不再要求当前完整绳子或精确手部模板。

数据目录domains/hololive_dreams/data/jump_rope_phase/：rotation_recipe.json配方、rotation_v1.json轨迹及来源。

已有录像20261003-135733-386995的约4.205～5.508秒单圈作为训练来源（精确范围以atlas.provenance为准）；静止背景用3.8～5.8秒素材30帧中值估计。离线蓝色筛选＋背景差异＋鲁棒5次多项式拟合26个阶段样本，缺失片段是拟合值。颜色筛选仅用于这段已知蓝绳训练，实时不使用它。固定路径库由样本循环插值，参考周期约1.303秒仅作初始速度，不能当实时按键间隔。

build_jump_rope_phase_atlas.cmd重建；可修改配方的cycle/background区间、sample_seconds、seed及输出，必须人工检查runtime/jump-rope/phase/atlas-training-contact.jpg。数据verified=false，有一圈拟合与闭合误差，不是密集真值；没有左右低空摇摆模板，没有危险阶段、离地/滞空/落地标定。原79次手动长按不作为新短按校准。

运行：run_jump_rope_phase_judgment.cmd启动3秒后聚焦游戏、显示曲线和阶段；F12/Ctrl+C/切走游戏停止，默认会话时限继承jump_rope_config.json.timeout（180秒）。持续识别丢失只降低置信度，不触发退出。run_jump_rope_phase_replay.cmd生成独立replay.json和annotated.avi。run_jump_rope_phase_validation.cmd还生成性能、时序与稀疏位置核对report.json；--no-video可只做分析。

输出目录runtime/jump-rope/phase/；last-result.json、loss-roi.npz隔离保存，主last-result.json仍指向最近运行，sessions保留完整每会话快照。新回放不覆盖A/B/B2的数据。所有result终局为unknown，保持模型不等于游戏成功。

## 已知边界和下一步

只有普通旋转路径。加速可更新推进速度，但明显速度变化、颜色/光照导致图像弱、投影路径变化以及低空摇摆都可能使阶段失配。预测会继续存在，应看灰/橙色状态、当前支持和误差，不能以“每帧都有曲线”宣称稳定识别。

1. 用多圈普通录像核对路径是否真的一致、端点/持绳姿势有多大偏移，分离建模与保留段验证。
2. 提取低空两个方向的独立轨迹，建立模式切换/多假设阶段跟踪；不要把rotation库强行当swing。
3. 解决加速重新定位、丢失后的速度不确定性；用已保存点回放阶段估计器，再用图像核对，避免错误点变训练标签。
4. 危险阶段、短按延迟和实际落地独立标定，再通过适配器接A或新控制器。此前C保持禁止输入。

验证数字、样帧误差和性能见本目录validation.md及runtime/jump-rope/phase/report.json，不只看有效帧数。


## 用户补充的运动规则（2026-10-04）

用户确认：左右低空摇摆会变换旋转方向。当前C路线强制展开阶段不反向、速度下限为正值0.02圈/秒，这个约束只适用于固定方向的普通旋转，不适用于反向摇摆。

因此左右摇摆不能继续使用“阶段只增不减”的估计器；需要独立轨迹/模式，以及有符号阶段速度、转折时的方向切换。反向时不应把负向残差持续解释为减速。位置连续约束仍应保留，方向反转不等于任意位置跳变。

录像中的速度下限现象与这一机制相容，但各错误时段是否确为摇摆反转，尚需逐段核对，不能把此前所有失败都归因于反转。观测门控顺序与不支持曲线仍提升置信度的代码问题也仍需修复。危险经过需区分两个方向；到脚时间用当前有符号运动方向估计，不以位置单独触发。本次仅补充规则与设计约束，尚未接入新控制逻辑。
