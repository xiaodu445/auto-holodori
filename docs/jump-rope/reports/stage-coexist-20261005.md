# 计数升级时保留旧速度分支，2026-10-05

用户确认：跨计数门槛后，当前技能可能仍使用旧阶段速度；无需强制等待技能结束，应允许“维持当前状态”与新阶段分支竞争。

独立入口 run_jump_rope_stage_coexist_judgment.cmd，仅判断；配置 jump_rope_stage_coexist_config.json；独立实现 src/modular_agent/realtime/coexisting_stage_bank.py。旧路线入口及数据不覆盖。

计数徽标更新 count_stage_index，仅提示新速度候选。stage_index 是有效播放速度阶段。每个播放实例记录自己的速度阶段，边界范围及曲线不会因计数变化而被旧实现按比例立即改速。新阶段同方向的各速度角色从同一个当前可见/预测位置开始，不跳到无关位置；保留当前模板原时钟、速度、曲线、方向及低空片段。

新阶段候选固定自身时间曲线参与评分，不逐帧追随当前模型校正；以与活动模型相同帧时间的分数比较，至少6个有视觉证据的帧、跨.12秒、平均优势大于.025才接管。没有证据继续当前阶段。候选播放1.5秒仍不胜出，重新从当前位置生成；这不是1.5秒后强制升级。候选去重和修剪保留阶段不同但角色相同的分支及其连续证据。

接管后整批切换到新阶段，清除旧阶段候选和比较证据，不等待外部技能结束信号；低空只比较同一运动模式，不凭计数直接改变方向。未校准减速候选不接管。标注保存在20261005-effective-stage.json。

限制：这是速度阶段共存机制，不能代替速度库校准。起点来自当前追踪，若已追错仍可能影响所有分支；仅同模式候选可能错过与升级同步的状态变化，原运动模式分支仍负责正反/低空切换。视觉相似或遮挡时可以保留旧速度阶段很久，不能把计数升级视作已确认新速度。旧记录的难度stage字段在新入口表示有效速度阶段，审阅页另显示计数阶段。

测试覆盖：徽标变化不修改活动时钟/速度/曲线/边界；同角色新旧候选共存且保留连续证据；没有视觉支持保持旧阶段；连续证据允许无技能结束事件时接管。
