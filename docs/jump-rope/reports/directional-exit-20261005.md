# 低空退出半摆约束，2026-10-05

本轮依据人工标注902、958、1087，原样保存于 `domains/hololive_dreams/data/jump_rope_samples/human/20261005-exit-directions.json`。原标注truth等空字段保持为空；方向规则来自用户文字说明，没有伪造额外人工像素真值。

## 硬规则与旧错误

用户确认：低空从后往前，才可能退出为反摇；低空从前往后，才可能退出为正摇。每个低空片段的退出方向必定相对进入前反向。不是当前摆动方向一变，就重新改写进入方向。

上一实验仅保证退出后反向，却把低空“重经过进入位置”当作退出边界。902对应负的低空图集速度，即从前往后，却在该进入位置重新生出反摇；958的正半摆则错过候选。恢复逻辑要等绳子明显抬到上方才补出候选，导致1087之后仍晚切。

## 新独立路线

只判断入口：`run_jump_rope_directional_exit_judgment.cmd`。配置：`domains/hololive_dreams/models/jump_rope/jump_rope_directional_exit_config.json`。原G、A自动、上轮clock-exit入口和页面均保留。

逐帧页面：`runtime/jump-rope/frame-review/directional-exit/index.html`，4010个原始采集帧，支持相同编号和时间戳标注。新增“从前往后/从后往前”“本半摆允许退出”“退出边界/接续图集位置”显示。

- 将低空进入边界、速度换档边界与退出边界分开。
- 进入前为正摇，低空正半摆（从后往前）才生成/接管反摇；进入前为反摇，低空负半摆（从前往后）才生成/接管正摇。
- 候选接管与上方图像恢复也检查同一半摆条件，过了转折进入错误半摆的旧候选不可接管。
- `swing_exit_coordinate=0.5` 使用低空图集的近似直绳经过，来自当前图集及958附近可见直绳；是可调几何接点，不是人工帧号或固定按键时间。通过时间模板反解成两种方向的退出时钟。
- 圆周接点由两个空间图集的距离和相同运动切向匹配计算。候选从该接点播放，不再不加区分地从圆周最低处开始。方向约束是用户已确认规则；几何接点仍属待实机校准推断。
- 保留原多档竞争、正值时钟和小幅校正；分支有后续证据才确认，普通低空经过不会直接强制换状态。

首次反摇确认从1103（23.808314秒）提前到1087（23.413778秒），提前约394.5毫秒。958到959差一个原始采集帧，尚未经过接点时不让候选提前播放。

同一开发录像稀疏状态检查11/11，状态切换8次、换向4次。55秒的已有可见点距离中位数从上轮37.21像素降到4.51像素；32秒约8.45像素，原G约6.98。本轮1875帧接受视觉支持，不是1875帧都正确，更不是准确率。

逐图复核还发现：1087虽切到了正确反摇状态，橙色预测曲线仍明显高于实际白色直绳，部分绿色支持落在角色/背景上。不能把rope_valid=true当作整绳位置已经正确；接点时钟和局部观测误支持仍需改进。本轮解决的是错误半摆生成和漏状态确认，不是1087全部位置误差。

1869仍为约0.81053圈/秒的慢档，加速反摇未解决。中间各段状态尚无密集人工真值，不能仅凭稀疏检查宣称整段无误。仍不推广为默认自动，不发送空格。
