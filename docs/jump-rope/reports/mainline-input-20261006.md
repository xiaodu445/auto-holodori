# 当前主线空格输入实测入口（2026-10-06）

用户认可阶段5之前的识别，要求先加入空格发送供本人实测。run_jump_rope.cmd无参数与菜单第5项现在运行当前guarded音频主线，原自动回退保留在run_jump_rope_local_motion.cmd。

使用：先将游戏留在跳绳开始界面，启动run_jump_rope.cmd；模型和声音准备完成后程序自动切回游戏，再开始这一局。必须实际看见Go并消失才开放输入。游戏声音需开启，使用默认扬声器回环设备；不使用麦克风。保持游戏前台，F12或Ctrl+C停止，失焦/窗口遮挡/关闭也停止。

主线包装器使用同一guarded模型与音频候选软证据规则：因果尾随2.6秒窗口、音频前缀、低空进入授权。声音识别在后台进行，窗口队列最多2份，优先较新数据；识别完成前无法使用该候选，过期音频不给加分。画面等待Go；用户补充正确绳子时机即可起跳，因此不识别角色、不等待落地。只保留0.30秒防重复间隔，不作为落地判断。绳子部分遮挡时可继续已建立的模板时钟。

空格发送为35ms同步短脉冲，按下后不进行下一次画面识别，期间检查焦点和停止。释放不依赖下一帧识别结果。按下/释放真实派发时间保存在会话日志；系统调度可能使实际时长有所浮动。跳跃计数仅在实际请求派发后登记，陈旧帧不会登记已发送跳跃。

初始起跳坐标由原录像人工空格按下对齐主线模板所得：正摇0.74，反摇0.25，低空前行0.12、回程0.98。按当前模式自己的时间映射换算到时钟，识别耗时纳入到达时间，35ms窗口内请求短按；不按录像绝对时间或帧号安排动作。这些是实测试用值，原人工长按不能验证短跳安全，仍需本人反馈调早/调晚。阶段5仍使用当前主线，独立终局实验没有被提升。
