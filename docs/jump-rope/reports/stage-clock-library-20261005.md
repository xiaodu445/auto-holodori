# 按阶段组织速度模板，2026-10-05

按用户建议，将速度数据库表示为“阶段 X → 正常 / 加速 / 减速”；低空左右摇独立保留。每个圆周模板分别保存正摇、反摇的圈内时间曲线，反摇不使用正摇倒放。模板的平均周期、允许微调区间和圈内曲线是不同参数。

- 原 A、G、directional-exit 等路线及入口保留，没有替换默认自动路线。

阶段暂沿用 0–9、10–29、30–49、50–69、70+ 次。界面显示阶段1–5，内部下标0–4。模板包含 branches.normal / accelerate / decelerate / low_swing；period_seconds 为平均周期，directions 为该方向独立拟合的时钟到位置曲线。缺失方向曲线使用旧先验，明确 direction_status=pending_calibration。所有新增曲线仍 verified=false，模板名称不等于技能已确认。

## 回放结果与未解决问题

采用新库但允许待校准先验竞争：4010帧，11个稀疏状态检查通过，8次模式切换、4次换向；55秒已有可见点距离中位数约1.65像素。11个检查不代表整段轨迹正确，1842帧有视觉支持也不代表1842帧识别正确。

关键人工速度标注处仍多次选择减速先验，没有稳定选中加速曲线。原因包括候选起始时钟受错误活动轨迹影响、相邻模板周期接近、视觉背景相位混淆，以及30次阶段徽标约晚1.3秒。不能宣称已经修好加速。

两个试验未采用：放宽速度恢复导致55秒距离退步到16.05像素；禁止未校准减速候选接管导致稀疏检查9/11、55秒距离53.36像素。它们保存在 stage-clock-library-recovery 和 stage-clock-library-calibrated-candidates，当前独立入口恢复较好版本。

下一步应校准候选起始相位和连续多帧分支证据，同时补齐每阶段各方向的实测时间曲线；单纯加锁或再加高档没有得到本轮证据支持。
