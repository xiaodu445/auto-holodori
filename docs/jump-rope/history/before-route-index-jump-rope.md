# 跳绳实时组件：开发中

双击 `run_jump_rope.cmd`，默认只判断、不发送空格。3秒后切回已打开的 hololive-Dreams；调用者须先进入小游戏。运行中失焦、窗口关闭、关键区域被外部窗口遮挡会停止并释放本会话输入。F12/Ctrl+C停止，退出窗口保留；`--no-focus` 禁用启动自动聚焦。

## 当前识别与控制

实时循环只看中间角色和两侧绳线，不识别标题、计数或生命，不依赖HUD建立跟踪或触发跳跃。`hud_valid`与`hearts`作为旧记录兼容字段均为null，不表示识别失败。入口、结束、计数/零失误验证由顶层或人工完成；当前没有这些自动核验器，也未接入顶层跳绳调度。

默认采集ROI为客户区相对[0.495,0.03,0.64,0.68]，约为客户区面积9.4%。原ROI约61%，此次减少采集像素约85%；不据此承诺相同比例提速。窗口移动或缩放后更新ROI并重置跟踪；建议开发时保持游戏客户区尺寸固定，不由组件擅自调整窗口。

角色：固定金发/墨镜角色局部模板，在局部搜索区匹配；置信度正确保留，不再被UI模板分数覆盖。角色姿态变化仍可能导致丢失。

绳子：蓝色HSV筛选→两侧窄探针→细长线段候选。首次获取只接受唯一候选；已有跟踪时根据上一帧位置和速度预测当前位置，在误差门限内选择且拒绝近似等价候选。历史超过0.12秒或时间倒退即重置，不把历史预测作为实际识别。

每个可见线段取多个(x,y)点，拟合短二次曲线，`rope_y`表示角色x=0.565处的估计高度，已替代原来的两探针平均高度。因此旧danger_y标定不能直接沿用。`rope_points`、`curve_error`、`probe_prediction`记录实测点、曲线残差和历史预测；均为游戏客户区归一化坐标，不是三维角度。遮挡处仅局部插值，不恢复不可见像素。

跟踪建立后可以在历史预测附近尝试更宽色域的细线候选；备用筛选只帮助找到绳线，不判断技能。用户确认变色仅是提示，后期不再变色。控制器忽略色相变化和变色标记，不以颜色取消预测、停止或进入unknown；速度估计及运动方向变化直接更新预测。颜色只作为局部视觉候选的辅助特征。

运动模式仍有rotation/swing独立控制路径，但当前视觉模块没有可靠的自动模式分类器；初始rotation是配置，不能宣称已实测识别运动模式。只有显式运动证据字段motion_mode可切换模式，不从颜色推导。具体危险方向和跳跃时机仍未标定。

控制：落地、起跳待确认、空中状态机；空格明确按下/释放；新帧覆盖待执行时刻，加减速更新预测。建立联合跟踪前最多等待20秒，之后长期丢失0.5秒停止；识别丢失与窗口失焦都返回unknown，不能等同成功。默认校准未完成，`--live`拒绝运行。

## 日志与回放

状态只显示角色和绳子有效性，不显示HUD。`runtime/jump-rope/last-result.json`包含实际FPS、采集/识别/控制/输入耗时、时间戳、客户区bounds、ROI以及最近600帧观测。采集同步消费最新图，无旧帧队列。程序启动异常保存在startup-error.log；`--verbose`输出完整统计。

```powershell
.\run_jump_rope.cmd --replay domains/hololive_dreams/data/jump_rope_samples/normal-no-input.avi --timestamps domains/hololive_dreams/data/jump_rope_samples/normal-no-input.timestamps.json
```

使用实际采集时间戳，而非录像名义60FPS。回放只读取本地素材，不显示图像、不操作游戏。

## 2026-10-03：颜色不参与控制
用户确认：技能提示可变色，跳到一定数量后不会变色以增加难度，实际需要判断绳速与摆动方向变化。已取消所有颜色到技能/模式映射、变色暂停和输入门槛；备用筛选误报unknown的问题被移除。回归覆盖相同运动不同颜色得到完全相同控制输出，以及无颜色变化时速度突变仍撤销旧计划。颜色改变后的轨迹跟踪仍需要验证，自动运动模式判断尚未完成。

识别丢失或初始跟踪超时后，组件在释放输入、关闭采集后保存 `runtime/jump-rope/loss-roi.npz`，包含最多 8 张每隔 6 帧取样的局部画面、单调时间及窗口坐标。实时循环只维护内存缓冲；保存时间不计入循环 FPS。结束提示区分角色、绳子或两者缺失；记录仍为 unknown，不能据此判断游戏失败或成功。

最新恢复策略：初始识别超过 20 秒继续搜索；已建立跟踪丢失超过 0.5 秒后清除旧速度、待跳跃和起跳状态，进入 recovering，继续局部视觉搜索。重新连续确认角色和绳子后重新估计运动，恢复前不输入。识别丢失本身不终止会话，仍受配置的总时限（默认 180 秒）约束；人工停止、失焦、窗口关闭和执行异常仍结束并释放输入。到时仍未恢复会保存局部诊断，结果保持 unknown。

会话结束时若最后仍缺少角色或绳子，包含人工切走导致失焦的情况，也会在释放输入后保存局部诊断。重新获取阶段使用 recovering / reacquiring_track，单独识别角色不会改写该状态。

最新识别方案：采集区扩大到窗口横向 35%～78%、纵向 3%～68%（面积约 28%）。优先检测黄色向下三角箭头，通过参考截图箭头与身体的偏移估计角色纵向位置；模板作为箭头缺失时的备用。两条绳子采样带随箭头横向位置移动，位置明显变化时清空旧关联。所有色相均可参与初始绳子候选，仍要求细长几何和候选唯一性；只连接采样带内约 18% 宽度的小缺口，拟合点取自实际可见像素，不把填补像素作为观测。大面积遮挡继续恢复搜索并抑制输入。箭头与身体偏移及光照适应仍需实机验证；实时耗时也需重新测量。

备用颜色提取改为分色相区间及低饱和亮色分别形成候选，避免黄色绳子与不同颜色的明亮背景合并成粗大组件；重叠区间的重复候选去重，依旧保留歧义拒绝、细长几何和时序门限。颜色仅用于找线条，不用于判断技能或运动模式。已增加黄色绳子独立获取及邻接绿色背景测试；真实黄色阶段仍需录到局部画面验证。
