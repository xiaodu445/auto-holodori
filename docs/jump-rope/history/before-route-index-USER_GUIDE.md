# 使用手册

## 顶层 Agent

双击 start_agent.cmd，输入“启动holodori”或“打开强欲之牌”。启动与进入小游戏的链式调用已由用户实机确认；界面版本变化和未知状态仍需人工引导。

任务开始由联网模型先观察并选择技能；launch_game 通过Steam启动/切回，再由本地启动树处理登录奖励到自由主界面。强欲之牌入口组件只在模型判断和执行器复核初始条件符合后接管，到实际High&Low界面结束，不下注。

任务中直接输入补充指示或 /guide 指示；看到已排队和已接收才算生效。/stop（不区分大小写）或F12停止；停止会话需重启。/logs on/off显示隐藏浮动日志；/status查询状态；/observe默认full；/windows查看当前窗口；/models、/model配置名切换模型；/quit退出。

默认任务步骤不限，但网络重试、本地组件、持键时长和错误恢复有局部上限。--live 才发送真实键鼠；模拟模式不会完成真实任务。

## 不依赖联网模型的入口

- run_game_startup.cmd：Steam启动、奖励处理，到自由主界面结束。
- run_greed_cards_entry.cmd：本地导航到实际High&Low页面，不下注。

二者不要与正在操作的顶层Agent并行运行。加载文字会等待，闪烁提示可由有限中央点击推进。当前本地玩法/赌场时间选择仍未实现。

## 模板和知识

图片放 domains/hololive_dreams/data/template_sources/in_game 对应目录，同名JSON描述含义、角色和threshold；启动任务自动同步，也可运行 import_game_templates.cmd。现有模板（含启动图标）匹配阈值统一0.65，新建及导入模板默认0.65。具体见 docs/vision.md 和源目录README。

顶层共享经验在 knowledge/global，游戏内经验在 domains/hololive_dreams/knowledge。任务事实在 runtime/memory/task_sessions；完整决策/反馈保存在事实记录，终端显示简化输出。模型 write_knowledge 记录需标注来源与验证状态，不能保证每次主动保存。

## 识别与升级

现有顶层及决策树保持完整full，不截断模型收到的屏幕报告。新接口支持独立开关、桌面区域、指定文字/模板搜索、等待与取消，可供以后按状态优化。Python/MCP用法见 docs/general-vision.md。配置模型和密钥见 docs/models.md；操作接口见 docs/computer.md。

按目录知识检索已接入：先列目录/标题，再按领域、目录或文件分页读取；历史日志默认排除。Skill只发当前领域调用元数据。详见 [知识与技能上下文说明](knowledge-routing.md)。

## 跳绳组件（开发中）
双击 run_jump_rope.cmd 默认只判断并自动切回游戏；退出窗口保留，失焦及错误原因可见。当前识别与跳跃时机未标定，不能自动游玩，--live 暂拒绝。见 [跳绳说明](jump-rope.md)。

手动操作录制：双击 record_jump_rope.cmd，3 秒后聚焦游戏，自己用空格跳跃，默认最多 120 秒。F12、Ctrl+C 或切走游戏停止。输出 runtime/jump-rope/recordings/时间目录：screen.avi（游戏客户区、最长宽度 1280、目标 60 FPS）、timestamps.json（与已编码视频帧逐项对应、含实际采集时间和窗口坐标）、inputs.json（空格初始状态及按下/释放、焦点丢失事件）、summary.json（FPS、丢帧及结束原因）。录制器不发送输入，不记录其他文字按键。空格按高位状态以目标 1 ms 轮询，实际调度存在误差、极短点击可能漏采；视频 nominal FPS 不代表实际时间，分析以时间戳为准。--duration / --fps / --width 可调整。不要同时运行自动输入组件。

实时标注：run_jump_rope_preview.cmd 为实验输入加诊断窗口；run_jump_rope_preview_judgment.cmd 为只判断加诊断窗口。窗口显示局部游戏画面、绿色真实绳子点、青色有效拟合曲线、紫色角色横坐标处的绳子位置、黄色箭头、白色落地基准和橙色试验区间；红色菱形为短遮挡预测，不代表当前真实识别。参数区显示 FPS、角色/绳子有效性、位置/速度、曲线误差、候选数量、ground/consumed/outstanding、实际控制 down 和 trigger/blocked 原因。原生窗口使用不激活样式；有空间放在游戏右侧，否则放在游戏左侧的非采集区，不能拖入采集区域。最新帧替换，不排队，显示最高20FPS；控制频率仍由60FPS目标循环管理。记录含 preview_submit_ms 和独立绘制耗时。窗口随会话停止关闭，F12 / Ctrl+C / 切走游戏仍停止释放。参数文字用英文以便实时绘制。

2026-10-03 整绳诊断v2：修复光流点和重新搜索曲线可能乱跳的问题。光流只是位移线索，41个点是沿曲线参数的采样位置，不是41个永久对应的绳子物质点。此前重新搜索候选可直接替换曲线、无效拟合污染历史，且逐点光流更新可造成曲线折曲；现改为先将可信光流位移拟合为平滑形变场，再用当前可见边缘修正预测模型。所有拟合候选在写回历史之前统一检查位移、预测残差、投影长度变化；不通过只短时预测，不更新测量时间/速度。
部分遮挡不再要求两侧同时露出：已建立轨迹的时间候选可凭至少10个、沿曲线跨度至少12/40的分散可见支持继续拟合，拟合后支持覆盖至少25%；只可借用最近120ms内达到完整支持门槛的形状，局部支持不能刷新这份完整形状的时间，防止错误片段无限续期。首次获取仍要求完整的更高支持门槛。被遮挡部分由上一帧曲线、速度及低维形变约束推算，不能标成当前测量。所有支持消失最多预测120ms；之后继续搜索，重新取得需连续3帧一致候选并增加track_id，不能冒充原轨迹的连续测量。画面点的measured/predicted/unknown含义保持不变。
whole_continuity配置仅作用于整绳诊断：max_speed=6.0（归一化二维位置/秒）、max_acceleration=90.0（/秒²）、position_noise=0.008。预测残差门限随实际帧间隔变化，为noise+0.5*acceleration*dt²；这些是实验容差，不是已实测物理上限。预览显示track_id、tracking_status、累计continuity_rejections和最近检查残差；rejected计数是候选数，不是丢失帧数。whole_observed_points只发布已接受拟合的边缘点。
入口保持run_jump_rope_whole_judgment.cmd，只判断、不发空格；原local_motion自动跳跃未修改。回放验证文件whole-rope-continuity.avi、whole-rope-continuity-report.json。连续性改善不等于认对绳子；静态背景、端点先验和大面积遮挡仍可能导致跟踪中断，不能宣称已达到全技能可靠控制。

2026-10-03 整绳形状模型实验v3（默认关闭）：用户要求利用静止背景、固定平滑绳形、连续运动及可见片段补全。新增--whole-rope --whole-shape，入口run_jump_rope_whole_shape_judgment.cmd、run_jump_rope_whole_shape_replay.cmd；仍只判断，全部实时输入路径被拒绝。whole_shape_model=false保留v2默认，现有local_motion自动跳跃、高低牌和顶层全屏观察不受影响。
模型复用人工参考弧形，高/低弧使用两个方向的形状先验；用幅度、受限不对称、两端垂直偏移及两端水平偏移共6个参数拟合当前可见片段。水平端点修正±0.02窗口宽、垂直修正±0.035窗口高，模板手部位置只当先验；模型端点显示预测状态，不能作为当前绳像素测量。4次鲁棒加权拟合抑制局部异常，隐藏部分由同一组参数决定。
颜色无关的细条横截面检查：沿候选法线对比中心与两侧2/4/6像素，支持亮绳或暗绳，仍需可辨对比。增加每像素近期亮度范围（上/下包络每帧回落2灰度），变化不足10的静止位置不能发布测量；这不是完整背景分割，对动态光照仍可能误判。角色身体核心位置范围是几何排除先验，不能当自动检测框；可能排除实际露出的绳片段。弧形族的视觉采样合并计算，测试核对批量与逐条结果一致。原连续性和遮挡过期约束保留。
验证：322项测试通过，包括曲线异常折曲、局部阻挡异常点、静止绳线附近动画、实验默认关闭与模式组合检查。同一4010帧/约88秒录像，v3接受拟合672帧（v2为979），149次轨迹获取；有曲线的1636对相邻画面95分位位移0.0370，超过0.06共9对（v2为29/2205对）。样本集不同，不能据此宣称准确率或整体更稳定。
