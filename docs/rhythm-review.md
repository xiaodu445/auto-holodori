# 音游录制与逐帧分析

## 试验：六键常按，独立音符前松开重按

2026-10-19更新：全松组的预测目标跨度最多10ms，不按轨道各自触发。松开期间
可以补入迟确认成员；恢复后100ms内确认、且目标属于同一个10ms时间组的轨迹
只记录coalesced_late_group_head，不再松按。整组总跨度限制避免0/9/18ms连锁合并，
30ms连续音符仍各自触发。初始同组取目标中位数作为公共重按目标；窗口建立后
新增成员不再往后推迟该目标，以免不断吃掉提前量。当前input_offset_ms=0，
合并窗口10ms不是输入补偿10ms。旧小窗口说明属于历史行为。

当前六键入口默认--release-scope all：确认音符目标前约30ms整组全松，到提前10ms
后的目标时刻六键一起恢复；3ms内的和弦合为一次窗口。最后--release-scope target
可回退旧单键松开。--no-record仍默认，录制开关不变。整组恢复可能触发附近其他
音符，假设“相邻键状态影响判定”尚未证实；请用同一谱面比较FAST/Bad与长按Miss。
若识别/调度已经太晚，仍保留8ms最小目标松开窗口，不保证硬件重按绝对准点。
启动时打印input mode/release scope/offset，便于确认运行的入口和补偿是否正确。

六键模式持续输入保护现在跟随本次--duration（默认600秒，最高1800），避免
通用30秒保护与“总有键按住”冲突；其他输入工具默认30秒保护不变。
F12、失焦、运行时长上限仍会停止。停止后用专用release_all收尾，失败仍在
cleanup_error中报告，不靠忽略异常宣称已松键。

run_rhythm_all_held.cmd启动--input-mode all-held，默认--no-record、不录制视频或全量
诊断。需要录制时使用run_rhythm_all_held_record.cmd，或附加--record；选项以最后
出现的开关为准。--preview仍可用。关闭录制不创建live-reviews会话，不编码/写帧，
但原有基础输入审计仍保留。旧的run_rhythm_full_song_live.cmd仍默认带录制。
旧入口仍为normal，
可随时回退，不要同时运行两个入口。关闭游戏AUTO，保持游戏前台，F12停止。
六键是持续保持，不是周期性六轨连打。已确认的独立音符到达目标前约12ms释放
对应键，到原预测时刻重按并保持，松开窗口目标至少8ms；检测太晚时宁可稍晚
重按保证释放窗口，不声称实际OS间隔严格8ms。和弦按对应轨道分别处理。
同键同目标的重复轨迹合并；未确认轨迹不制造松键窗口；轨迹消失后也恢复基线，
不会永久松开。红区硬屏蔽、提前10ms与F12/失焦/异常释放仍保留。

此模式完全绕过长按路线和颜色判断，解决持续保持需求，但“游戏允许提前保持、
空按无惩罚、重按窗口不伤长条”是待实机验证的前提，尤其要观察特殊键和误触发。
分析页注明输入策略，事件release_before_head对应释放计划；实际API调用见时间轴。

## 自动按键＋整首歌同帧记录

双击run_rhythm_full_song_live.cmd，关闭游戏内AUTO，且不要同时启动另一个
音游自动按键脚本。切回游戏等待前台后开始；默认最多600秒，结算后F12结束，
失焦/窗口变化/预览关闭同样停止并释放按键。可附加--preview、--duration 900、
--bpm 240或--offset-ms 0。该新入口明确带--live，旧只录制入口仍不发送输入。

与按键共用同一截图，不创建第二个采集器。编码、JPEG和JSONL写盘在有界队列
线程完成；队列溢出/写盘错误/低磁盘余量停止，不静默丢弃诊断帧。增加录制开销，
未验证实机帧率，不承诺与未录制完全同速。建议10GB空间，初始至少2GB。

runtime/rhythm/live-reviews/<时间>包含screen.avi、timestamps.json、frames、
live-decisions.jsonl（全程决策/按键调用）、inputs.json、summary.json和analysis.json。
每个输入尝试保存API调用begin/end及success；失败不画成已成功按键，API成功也
不证明游戏收到或Perfect。末帧后的退出释放保留在input_attempts/JSONL，视频
时间范围外的事件不应强行与结算画面对齐。网页是当次记录，不再离线重跑控制器。
每30秒一段，总览自动打开。F12后先安全释放按键，再等待编码完成和导出页面。

## 整首歌入口

双击record_rhythm_full_song.cmd，切回游戏从歌曲开始录制；可以录AUTO，或录已有
按键程序的实际运行。录制器本身不按键，不会自动启动另一套按键程序。
唱完到结算后按F12，失焦也会结束；默认最多10分钟，可用--duration 900改上限
（最高1800秒）。不要录制中切去查看预览，否则会失焦提前结束。
结束后自动分析完整已录视频并打开全曲总览，每30秒一个本地逐帧页，支持前后段
导航。原图逐帧保留，默认960宽，数分钟可能数GB，建议至少10GB空闲；低空间
会提前停止录制。分析耗时取决于录像长度，不只前20秒，也不会自动判断歌曲结束。

已有整首录像拖到analyze_rhythm_full_song.cmd，默认分析到EOF；可加--duration截断。
整首页仍是当前逻辑离线重算，真实系统键状态是按截图循环采样，不是精确发送日志，
也不是游戏Perfect/Miss标注。现有自动按键last-result仅保留600帧，不当全曲真值。
全曲原始分析保存在analysis.json，浏览器分段加载而非一次嵌入全部帧。反馈按录像
SHA256和源帧保存，导出包含标注时间；分享时保留整个review目录和frames。

## 20秒快速入口（保持不变）

先用游戏内AUTO播放谱面，运行record_rhythm_review.cmd，切回游戏。默认录20秒，
F12/失焦提前结束。录制器不发送输入，结束后离线分析并自动打开分析页。
它保留单调时钟时间戳、视频及按帧采样的S/D/F/J/K/L系统键状态。
AUTO通常没有系统键事件，不能把空记录当作程序漏按。

已有视频直接拖到analyze_rhythm_video.cmd。默认分析前20秒，可用命令：

    analyze_rhythm_video.cmd "D:\path\auto.mp4" --duration 60 --start 0 --title-bar 38

录制器输出为客户区，title-bar=0。自行录的含Windows标题栏视频可去掉38像素，
但标题栏高度可能随DPI变化；不支持自动定位任意桌面截图里的游戏窗口。
变帧率视频应提供--timestamps；没有sidecar时按帧号/名义FPS处理，时机误差需注意。
每次输出独立目录runtime/rhythm/reviews/<session>，不会覆盖旧录像。
open_rhythm_review.cmd打开最近成功的分析；目录中的index.html也能直接打开。

界面支持空格播放、左右逐帧、帧号跳转、原图/识别框/拖尾/轨道覆盖层开关。
六键时间轴区分离线模拟和录制到的系统按键。点击轨迹看ID、速度、预计到达时间、
跟踪丢失年龄及位置曲线。疑点跳转为启发式提示，不是识别正确率或游戏Miss证据。
长按释放时机、速度预测偏差可结合原画面逐帧检查；本工具不自动读Perfect判定。

点击原画面标记漏检点位，选择标签并保存备注。反馈先存在本浏览器，必须点击
导出反馈JSON才能交给后续分析。导出包含录像SHA256、源帧、时间、点位和配置。
原录像和生成的frames不能只移动其中之一；分享/移动时保留整个review目录。
没有音频回放；当前模拟使用1ms离线截止时间步进，不包含真实系统调度延迟。

几何统一来自reference_1：1264×711客户区，判定线中心y573，左右可玩边界x122/1142，
不含两边装饰区域。实时预览和离线页读取相同geometry配置。

24项音游测试通过，浏览器验证逐帧、播放、轨迹选择、反馈导出、640宽布局。
使用合成录像验证流程；实际AUTO录像和录制效果仍待现场反馈。
