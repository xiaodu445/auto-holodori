# 厨房三消录制

双击项目根目录 `record_kitchen.cmd`，5秒内手动切回游戏并进行操作。
默认录制300秒、30 FPS、整个窗口客户区、原尺寸（编码要求偶数对齐）。
不自动导航、不激活窗口、不发送鼠标或键盘输入，不录音。
F12、Ctrl+C、失焦、窗口移动/缩放均停止。

自定义示例：`record_kitchen.cmd --duration 600 --fps 30`。
其他窗口：先运行 `record_kitchen.cmd --list-windows`，再指定 `--window-handle 数字`。
窗口标题默认精确匹配 hololive-dreams，可用 `--window-title` 覆盖。

输出目录：`runtime/kitchen/recordings/时间戳/`：
- screen.avi：MJPG视频（有损），适合回看和初步数据采集。
- timestamps.json：每个编码帧的video_index、frame_id、实际单调时钟时间和客户区边界。
- inputs.json：左右键初始状态、按下/释放边沿、屏幕/客户区/归一化坐标及是否在客户区内。
- summary.json：停止原因、编码丢帧与尺寸、时钟说明。

视频是恒定帧率；真实时间以timestamps.json为准，不使用帧号/fps代替。
鼠标采用目标2ms轮询，不是系统事件钩子；可能漏掉极短点击。点击时间是观测时间，
不能证明游戏接收或成功取走物体。初始按住状态不算一次新点击。
桌面截图要求游戏无遮挡；失焦能停止，但不保证检测所有覆盖窗口。
原始无损训练样本导出与点击效果标注留待下一阶段。

复用WindowCapture（窗口/DPI/焦点/F12检查）、跳绳offer_latest编码队列策略和原有CMD Python环境。
录制生命周期沿用跳绳实现，厨房单独记录鼠标，不改变原跳绳入口。
只读观察器不产生UI转换，因此不创建交互策略或执行菜单重试。
离线测试覆盖鼠标坐标/边沿、失焦停止、视频时间戳对齐、资源释放和初始化失败。
尚未验证真实游戏录像、真实鼠标采样完整性与长时间磁盘性能。
