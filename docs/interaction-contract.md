# 全游戏交互协议（2026-10-21）

这不是给每个按钮增加无条件连点。基础约束是：输入发送成功≠游戏接受≠业务完成。所有场景都要声明源页面、目标、后置条件、重试/等待/不重试策略；新模块禁止再次手写“点一次然后等到底”。

通用执行机制：`src/modular_agent/agent/interaction.py`（转换循环、超时/重试预算、窗口检查）与 `agent/ui_actions.py`（输入发送及目标边界检查）。游戏适配：`src/modular_agent/domains/hololive_dreams/interaction.py`（场景策略、游戏状态映射、可交互按钮语义）；文字弹窗证据仍在领域 `popup_recovery.py`。详见 [日常与交互的分层](daily-layers.md)。

## 场景策略，不能混用

| 场景 | 基础策略 | 必须特别考虑 |
| --- | --- | --- |
| 启动、世界/地图导航、通知入口 | navigation | 新鲜源页面成立才允许补按，焦点/遮挡/目标边界检查 |
| 工作、礼物、轮盘、任务、成就 | claim | 奖励出现后不再补领取；轮盘入口不消失不是失败 |
| 活动、演出菜单及已知弹窗 | menu | 只执行已登记语义，优先当前弹窗；按钮启用且位置新鲜 |
| 对话 | dialogue | 每次只推进已识别对话，退出后禁止补E重开 |
| 加载、多人等人 | passive | 只等，不点决定成员，不因人数/倒计时变化而补按 |
| 实时打歌 | realtime | 由原打歌引擎独占，不套菜单重按，不改变音符算法 |
| 下注/消费等非幂等操作 | nonrepeatable | 默认最多一次；没有业务幂等证据不能自动补发 |

`SCENARIOS`及`policy_for()`显式注册这些策略，未登记场景拒绝创建策略。默认菜单预算3次、间隔2秒、25秒总时限、两帧确认；可按场景显式调整，不等于游戏保证在该时限内响应。

## 共同执行顺序

1. 观察新帧，检查停止信号、前台窗口和遮挡。
2. 错误/购买确认先停止；奖励、升级、对话及登记弹窗先处理，不能透过弹层确认背景页面。
3. 只有预期目标页稳定出现，才确认这一步完成。
4. 源页面仍成立、同一语义目标仍可用、未进入奖励处理时，按RetryBudget决定是否发送/补发。
5. 未知窗口先局部模板；按需重新观察开启OCR及按钮形状，严格匹配登记标题与按钮文字。裸OCR文字、矩形、蓝底均不够：还需文字置信度、按钮关联与蓝白启用色。购买、充值、兑换、成员确认均禁用自动恢复。
6. 无法证明控件可用就等待到预算并记录证据，不随意点空白；超时不得冒充完成。

登记弹窗文字可处理“确定/继续/下一步/关闭”，关闭叉号另有弹窗右上布局约束，禁止窗口标题栏X。未知标题不会猜测其按钮意图，应增加登记和截图回归。
