# 奖励识别扩展交接

本文记录当前代码已有接口及后续设计约束。以下“待实现”不是现有能力或已验证行为。

## 当前已有的接入点

| 接入点 | 当前实现 | 边界 |
| --- | --- | --- |
| `src/modular_agent/domains/hololive_dreams/states.py` | `UIState.REWARD`、`RANK_UP`；根据GET、模板及world_features判断 | 只识别页面状态，不识别全部物品和数量 |
| `daily_tasks.py:DailyTasks.capture` | 捕获后先调用奖励记录器，再由业务流程处理页面 | 当前仅日常捕获链，不是所有小游戏的全局事件总线 |
| `daily_journal.py:RewardRecorder` | `record_rewards`开关、展示层episode去重、读取回调、证据事件 | 不核实背包入账，不提供完整多页去重 |
| `local_models.py:execute_daily/run_daily_tasks` | 可信Python可注入`reward_reader`、`on_event`；转交DailyTasks | 模型JSON不能提交Python函数；能力适配器尚未自动安装具体读取器 |
| `agent/task_plan.py` | 保存能力结果，模型可用结果字段继续规划 | 不因识别到奖励就自动将任务升级为verified |

`reward_reader(report)`是同步回调。当前只要求返回字典，且`items`如果存在必须是列表；物品字段尚无完整统一校验。建议的物品字段如item_id、name、quantity、confidence、来源区域等，需要在正式接入时定义契约，不能把建议字段视为现有保证。

读取结果保存在每条记录的`reader_result`中；当前不会自动合并到外层`items`，也不会据此把`amounts_verified`改成true。读取器异常记录为`reader_error`，日常流程仍可以继续；当前没有“识别失败必须保留奖励页面”的策略。

记录器在奖励层首次出现时读取一次，连续可见时不重复调用；观察到奖励层消失才结束episode。同一层内换页、动画结束、数字改变或第一次读取失败，都不会自动触发第二次读取。因此现有回调可以接入简单读取器，但稳定识别和多页支持仍需要新状态机。

## 后续目标流程（待实现）

```text
发现奖励层 → 等待布局/动画稳定 → 识别物品及数量
          → 保存证据并按页去重 → 读取后续页（如有）
          → 确认记录完成或采用明确失败策略 → 关闭页面 → 观察后继状态
```

识别和关闭应由同一个领域奖励处理器协调。仅把耗时模型塞进现有回调，并不能自动获得翻页、等待、重试和关闭协作。

设计时应补齐：

- **同帧数据契约**：当前report有结构化文字、模板、状态和时间，不能假定它包含原始图像。需要像素的识别器应取得对应帧或有效帧引用及ROI、窗口原点、捕获时间；不能另截一张图后继续用旧坐标解释结果。
- **稳定等待**：用连续新帧判断布局/内容稳定，有识别与总时长预算；旧帧或动画中读数不能当稳定证据。
- **结果格式**：统一物品ID、显示名称、数量、置信度、证据区域、识别方法、未识别项与错误。数量不确定时保留未知，不能填0或编造。
- **分页和去重**：区分奖励展示episode、页面、物品行和任务来源。允许同一物品出现在多个合法奖励页；连续帧去重不等于跨任务交易去重。
- **读取与关闭顺序**：先记录有效结果或明确失败，再发送关闭。识别失败采用继续关闭、保留页面或交回模型中的哪种策略，应显式配置；停止或失焦时不强行收尾。
- **统一接入**：日常、启动树、`return_to_free`、多人和各小游戏结算入口逐一接入。当前返回自由界面的恢复器会确认已有奖励层，但不调用日常的RewardRecorder，不能声称开启record_rewards就覆盖所有入口。
- **日志与汇总**：保存任务/步骤ID、帧时间、episode/page关联和证据位置，分别展示已读内容与未确认内容。跨任务汇总应处理币种、重复来源和未结算结果，不能直接把所有检测相加。

## 完成与到账证据

至少保留以下不同含义：

1. 观察到奖励页面。
2. 读出了页面显示的物品和数量。
3. 观察到页面确认/结算流程结束。
4. 通过对应物品的可靠账户/背包证据核对到账。

前三项不能自动推出第四项。已有`amounts_verified`、`rewards_verified`和任务`verified`也不是可随意互换的字段；正式升级时应定义各自的验证范围。强欲之牌继续保留独立账本，不用通用读数直接覆盖其已确认现金流。

奖励识别不改变前置状态恢复的安全边界：业务尚未开始时可以按声明恢复后重试一次；已经领取或下注后结果未知，应核对结果，不能为了补截图再次执行领取或下注。

## 开发与验证位置

开发、样本整理和回归放在相邻`Game_agent_dev`，完成后仅提升运行代码、必要资产与说明，不把训练集、标注工具和测试目录放回运行仓库。实现时读取本仓库AGENTS.md、development-guardrails.md及interaction-contract.md；新增交互场景登记领域策略，复用现有输入、窗口检查和预算。

后续回归至少覆盖：动画未稳定、延迟奖励层、重复帧、多页同物品、同层内容更新、低置信度/缺字、读取异常与超时、关闭输入丢失、关闭控件禁用、GET→RANK UP连续弹层、取消/失焦/窗口移动，以及“读出数量但未核对到账”。离线样本通过与实机通过分别记录。

当前未实现完整奖励内容识别器、多页奖励处理器或到账核对器。相关现有调用方式见[daily-task-api.md](daily-task-api.md)，模型接口与恢复规则见[CAPABILITY_PLANS.md](CAPABILITY_PLANS.md)。
