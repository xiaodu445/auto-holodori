# 多地图建图工作台

双击 `mapping_workbench.cmd`。每张地图单独保存名称、录像列表、拼图项目、手工底图和参考配置；不会根据全局最新时间戳把另一张地图拿来修复。

## 新地图流程

1. **新建地图**并命名。默认复用本游戏既有小地图布局；布局不同时用“小地图布局配置”选择含minimap字段的JSON，仅复制ROI，不导入地图坐标。
2. **新采集**：你在游戏内手动走动，8秒准备，默认最长20分钟/4FPS，另有3000帧预算，以先到为准。已启用光锥和随机标记排除，截图仍保存原始未遮罩版本。光锥方向不清不会写入底图；不能保证初扫无漂移，长路线需人工检查。
3. 选择录像，点**打开手工拼图/掩膜**。自由拼图项目放在当前地图的alignment目录，按录像分别保存。已有别处录像可“导入录像目录”。
4. 手工拼图导出后点“刷新”；工作台会在本项目内找到导出。外部导出可用**绑定手工底图**选择对应patrol-config.json。只有这一张图的手工导出才用于修复。
5. **修复补图**：你手动重复走动，继续沿用光锥剔除、位置图优化和多观测合成。每次另建录像目录，不覆盖原结果。
6. 结束后选中修复记录，点**使用选中记录的地图作为参考**，再点**位置追踪**或**宝藏/路线标注**。手工底图用于修复初始化，参考图用于定位和标注，两者分别管理。

“续扫选中记录”需要其state.npz；会创建新输出目录。普通初扫支持续扫；修复图目前没有通用续扫检查点，需用原手工底图再采集，不能把缺失state.npz的修复记录当作初扫状态。

## 已有地图与标注

“导入已有地图”选择该图的patrol-config.json并命名，原文件保持原位。修复结果有明确source_config来源时会找到它的手工底图，不从其他地图猜来源。也可手动绑定手工底图。

旧宝藏/路线标注可“绑定已有标注项目”，需底图指纹相同。其他地图不会共享标注项目；底图几何版本变化后不能直接沿用旧坐标，旧项目及其底图快照仍保留。

项目保存在 `runtime/patrol/map-projects/地图编号/`。recordings为独立会话，alignment为手拼项目和导出，navigation为宝藏/路线项目，logs为各子任务日志。关闭工作台不强杀子任务；F12、失焦、窗口变化或停止文件仍由原采集器执行保存退出。切回工作台可能触发正常的焦点停止。

## 维护范围

工作台不启用自动探索或拾取，只启动已有被动采集/定位以及离线编辑器。新图初扫增加了逐帧光锥/随机圆点剔除和原比例滚动预览；原始截图保留，未知处留空。不同UI布局/场景仍需检查ROI、自由场景HUD及地图尺度，本轮没有新地图实机验证。

旧minimap_continue.cmd已去除固定录制路径：无显式配置时使用传统全局alignments目录最新手工导出；管理多张图请使用工作台，或显式传--reference-config。新地图不要依赖传统入口的全局默认选择。
