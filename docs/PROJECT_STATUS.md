# 项目现状与后续方向

更新：2026-10-26。本文是当前交接入口；历史报告中的测试数量、实验入口和性能数字仅属于对应版本。

日常任务实现与通用执行机制的边界见 [日常与交互分层](daily-layers.md)：重试预算、等待与输入发送在通用层，具体模板、场景判断和游戏流程在领域层。此次调整保留原有行为，后续仍需打磨状态与完成证据。

## 最初愿景

模块化、自扩展 Agent：通用模型处理理解、规划和未知情况；本地、低成本、可验证的 Skill 处理重复任务。观察 → 路由 → 执行 → 重新观察验证 → Experience → Memory。可复用经验经审核后进入知识库或固化成技能。

通用层为 `src/modular_agent/`、`config/`、`prompts/`、`knowledge/global/`；游戏资源集中于 `domains/<domain>/`。训练和实验暂留 `learning/`，避免仅为目录整齐改坏当前模型路径。后续逐模块迁移，不做一次性大重构。

## 用户确认的后续工作

1. **日常任务：优先打磨状态与流程。** 重新梳理每个任务的入口、等待、弹层、失败恢复和完成证据。区分输入成功、页面离开、任务完成与奖励到账；保留 unknown，不能靠无匹配或超时宣称完成。复用 `interaction.py` 协议及已有停止、焦点、预算和奖励日志。
2. **跳绳：保留全部标注，再评估更换模型和 GPU 调度。** 当前人工标签、原始 JPEG、历史帧映射、数据切分、权重和原录像共同保存。先分别测量截图、预处理、推理、排队、决策与输入耗时；再比较更大模型或其他模型、资源独占/并发、队列和旧帧丢弃策略。新模型独立实验及导出，未验证前不替换可用版本。
3. **厨房：继续补训练集、训练与调逻辑。** 已有标注、诊断训练、权重与 TensorRT 实验；早期 README 的“尚未训练”只描述当时状态。当前缺的是足够覆盖新对局、遮挡、易混类别、托盘和订单变化的数据。先审核真实标签和划分，再训练，单独验证识别和动作策略；同局留出不能当作泛化成功。
4. **钓鱼：维持当前可用版本。** 简单、粗糙是已知状态，有精力时可整体重做，暂不以目录整理为由调整控制算法。

## 工作区和数据边界

`Game_agent` 是自用主工程。相邻 `JumpRopeRelease`、`JumpRopeAMD`、`JumpRopeUnified` 是独立发布/后端工作区，不能混入本仓库或回写自用模型。详见各自工作区说明。

源码、文档、启动器、运行所需小模板进入 Git；环境、凭据、日志、录像、训练集、权重、引擎和构建产物保留本地。**Git 忽略不代表删除，也不代表已有异地备份。** 训练资产的独立备份和运行依赖见 [资源目录](ASSET_CATALOG.md)。新电脑仅克隆源码不能立即运行所有训练模型。

本轮不调整游戏算法或用户配置，不启动游戏，不执行训练。旧报告保持可追溯，不再把历史通过数量当作当前验证结果。
