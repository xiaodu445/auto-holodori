# 领域模块开发规范

## 何时创建领域

当资源只适用于一个游戏、应用或业务环境时，创建 `domains/<domain>/`。例如 `domains/game_x/`。跨领域能力才留在顶层 `src/modular_agent/` 或 `skills/`。

## 领域资源要求

| 目录 | 内容 | 最低要求 |
| --- | --- | --- |
| `knowledge/` | 流程、版本变化、失败经验 | 以可复用结论而非操作流水账描述 |
| `skills/` | 专用 Skill | `skill.json`、实现、README、测试 |
| `vision_library/` | 图标/按钮模板 | 最小截图、环境、阈值和人工反馈 |
| `models/` | 小模型 | 版本、数据来源、评估结果、回滚说明 |
| `data/` | 训练/评估数据 | 授权与脱敏说明；大文件不提交 |

## 新 Skill 的最低流程

1. 先确认规则、模板匹配或 OCR 不能稳定满足需求，再考虑小模型。
2. 按 `docs/schemas/skill-manifest.schema.json` 写 `skill.json`。
3. 实现 `can_handle(state)`、`execute(state)`、`verify(before, result, after)`。
4. 至少测试：可处理成功、不可处理、执行后验证失败。
5. 写明适用界面、风险、失败模式与人类可复核的证据。

## Memory 写入规则

写入的应是未来有用的结论，例如“版本 X 后每日任务入口从任务页迁移到活动页”。不应写入每次点击的坐标或未经验证的猜测。

## 小模型接入门槛

专用模型进入 `models/` 前，至少记录：

- 为什么模板匹配/OCR/规则不够用；
- 训练和评估数据的来源及许可；
- 精度、召回率、延迟和硬件条件；
- 可部署格式、版本号和回滚到旧版本的方法；
- 与 Router 的适用条件、成本和置信度阈值。

没有这些信息时，模型只能作为实验资产，不能注册为自动执行 Skill。

## 当前识别扩展接口（2026-10-02）

识别模块保持原full兼容，新增独立OCR/UIA/CV/模板开关、桌面ROI、指定模板、单次缩放/阈值、find_text/find_templates/wait_for。详见 [识别接口说明](general-vision.md)。本地组件应通过这些接口减少无关计算，并保留未知状态与完整识别兜底；不缓存历史坐标，不同时控制键鼠。当前已实现启动与强欲之牌入口树，尚未实现下注/卡牌策略。
